User manual / For Developers

For Developers

Rebuilding the executable

python -m pip install pywebview pyinstaller pillow
build.bat

build.bat bundles app/ (including the 23 MB OpenCascade WebAssembly kernel) and razorcad.py into RazorCAD.exe with PyInstaller. If RazorCAD is open, the running copy is renamed to RazorCAD.old.exe and the new build is used from the next launch.

installer\build_installer.bat builds RazorCAD.exe and then RazorCAD-Setup.exe. Set the version in version.txt first.

Code signing

Both builds sign RazorCAD.exe, the thumbnail DLL and the setup once a code-signing certificate is set up; until then they say "Not signed" and carry on. tools\sign.py --check shows how signing is set up. installer\SIGNING.md explains how to get a certificate and set it up (a certificate on a USB token or in Windows by its thumbprint, a .pfx file, or a cloud signing service).

Regression tests

python tests/run_tests.py

This rebuilds the test parts in tests/parts with the real geometry kernel in headless Microsoft Edge. It compares every body's volume, area, faces and edges (and flat patterns) with tests/expected.json, and the drawings of six test parts with their stored line counts and sizes. It also runs checks done as a user does them: sketching, dimensioning and extruding, drawings, assemblies, mates, references, standard parts, collisions, assembly features, macros, accessibility and more. It needs Python's playwright package and exits with 1 on any difference. --update stores new expected results, --only runs some of them, and --make-parts makes the test parts again from tests/make_parts.js. On a PC with 12 or more processor threads the run is split over several pages side by side (--jobs N; --jobs 1 runs everything in one page): about 27 s instead of 65 s on 24 threads. See tests/README.md.

  • Timings: every run's times are kept per machine in tests/perf-history.json (not in git). A test markedly slower than its usual time is listed under Performance; --perf lists every time and --perf-strict fails the run on a slowdown.
  • On GitHub the tests run for every push and pull request (.github/workflows/tests.yml), split over 6 machines side by side (--shard I/N, shared out by the times in tests/test-weights.json): some 15 minutes.

Releases

Pushing a version tag (for example v0.14.0-beta, matching version.txt) runs .github/workflows/release.yml: the tests, then RazorCAD.exe and the setup are built and a draft release is made with the setup, its read-me, checksums and notes from CHANGELOG.md (tools/release_notes.py). A version that already has a release is left alone. See installer/RELEASING.md.

The geometry kernel builds

app/vendor/replicad holds two builds of the same Open CASCADE bindings: replicad_single (one thread) and replicad_multi (threads, with shared memory). Both are built from source: Open CASCADE 8.0.1 with two speed patches (the same results), opencascade.js 3.1.0 (Emscripten 6.0.5) with whole-program optimisation, replicad's bindings (commit a0bc495) with RazorCAD's additions, and tools/native/surface-patch.cpp (tools/native/README.md); tools/patch_surface_kernel_loader.py adjusts their loaders. The kernel worker loads the multi-threaded one when the app asks for more than one thread and the page is cross-origin isolated: the desktop app's server, serve.py and the tests' server send Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp for that. The website takes files up to 25 MiB, so tools/build_web_app.py publishes a bigger kernel in parts, which the worker joins.

The website and the browser version

python tools/build_website_docs.py builds the online manual (website/docs) from this manual's source and the browser version (tools/build_web_app.py). The browser version is built in its own folder, RazorCAD Web next to the project folder, with both kernels (website/_headers serves it cross-origin isolated, so it runs the multi-threaded one where the browser can), and copied from there into website/app; it carries the geometry kernel's signature so the browser keeps stored models per kernel.

python tools/check_site.py checks the website as it is served (razorcad.com, or another address): its pages, the browser version's isolation headers, and the browser version itself in headless Edge (it starts, and a multi-threaded kernel builds a part). GitHub runs it after each push that changes the website (.github/workflows/site-check.yml).

Working on the UI

Run python serve.py and open http://localhost:8765/ in a browser. In that mode files are downloaded instead of saved through dialogs. Set the RAZORCAD_DATA_DIR environment variable to keep a test run's recent-files list separate from your own.
