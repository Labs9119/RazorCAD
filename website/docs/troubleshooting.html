User manual / Troubleshooting

Troubleshooting

Crash reports

RazorCAD writes a crash report whenever something goes wrong, to %APPDATA%\RazorCAD\crashes\<date_time>_<kind>\. Open the folder with Help ▸ Open Crash Reports Folder. The start window mentions new reports. The newest 30 are kept.

FileContents
report.jsonThe kind of failure, the error message and stack trace, what RazorCAD was doing (mode, Property panel, sketch tool, selection, feature errors) and system information
session.logThe recent actions of the session, newest last
part.rcadThe part that was open, so the problem can be reproduced

Kinds of report: ui-error, kernel-error, kernel-worker-crash, python-exception, native-crash and unexpected-shutdown (a session that ended without closing normally, found at the next launch).

Reporting a problem

Help ▸ Report a Problem…, or Report on GitHub… in the start window's crash notice, turns a crash report (or a plain description, without a crash) into a GitHub issue. The report holds RazorCAD's version, Windows, what went wrong and the last lines of the session log; you see the whole text first and can edit it. Your user name and folders are taken out, and the part you were working on is not included. Open GitHub Issue opens RazorCAD's new-issue page in your browser with the text filled in; nothing is sent until you submit it there. Copy Text copies it instead.

Speed on your PC

How many geometry kernels work at once comes from the PC RazorCAD runs on: one per processor thread beyond two (left for the window and the rest of the PC), and about 1 GB of free memory each beyond 2 GB, read from Windows when RazorCAD starts; at least 2, at most 16. Assemblies build their parts side by side in them, drawings draw their views in them, and each open part keeps one (up to half of them). Kernels that are idle for a few minutes are stopped to give their memory back. A big imported STEP file's bodies are meshed by several kernels at once when that is quicker (64 bodies with 6784 faces: 1.8 s instead of 5.4 s). Crash reports note the figures, for example "up to 12 at once (24 threads, 14.8 GB free)".

Each open part's kernel is multi-threaded: Open CASCADE splits booleans (cuts, joins and the features built on them) and meshing over several threads, and faces and edges are read and boxed in parallel too. The first part you open gets all the processor threads but two (at most 22); each further part, assembly or drawing kernel gets half the threads beyond two, from 2 to 8. On a PC with 4 or 5 threads the first part gets all but one and the others one thread; with 2 or 3 threads the first part gets two (about 30 % quicker than one on two cores) and the others one. Parts full of cuts and large imports gain most: 16 test parts rebuild about three times faster than on one thread (on a PC held to 4 threads, 9.2 s instead of 16.3 s). The browser version at razorcad.com/app does the same in a current browser (the website serves it cross-origin isolated, which shared memory needs). The session log says which kernel started ("Geometry kernel ready: multi-threaded, 22 threads").

Cuts made together: a run of cut features (extrude and revolve cuts with a blind, mid-plane or through end, holes other than tapped ones, and patterns and mirrors of cuts) is made in one boolean instead of one after another, each on a body with more faces than the last. The cuts wait until a feature needs the body as it really is (a fillet, a hole ending on a face, anything that picks model geometry) or the rebuild ends. The Giant Golfball (178 dimples) rebuilds in 2.5 s instead of 4.7 s, with exactly the same result. Editing the last cut feature makes only its own cut again: the rest is remembered.

Editing a feature meshes again only the faces and edges it changed, and a part reopened from the model cache picks up where it left off without being built again.

Common problems

ProblemWhat to do
A fillet or projected edge loses its edge after a big changeEdges made by an extrusion are found by what made them; others by their geometry and the faces beside them (see References that follow edits). If one is still lost, Tools ▸ Fix References lists it: Edit to re-pick it, or Remove missing.
A mate moved to the wrong face, or shows a red !Mates find their faces again by geometry. A face that is gone is listed in Tools ▸ Fix Mates: edit the mate to pick it again.
A sketch on a model face doesn't follow the faceSketches put on faces before version 0.20.1 keep only the plane: right-click the sketch ▸ Change Sketch Plane… and click the face again. If the note says the face is no longer in the model, pick the face it should be on.
Project Edges can't see a sketchIt only sees visible sketches earlier in the history. Show the sketch first.
An STL body can't be filletedSTL bodies with thousands of faces can't be filleted or chamfered and don't offer pickable edges.
A fillet won't blend across two touching bodiesCombine the bodies first.
Open fails with a file filter errorFixed in 0.9.0-beta. Update RazorCAD.
Unsaved work after a crashReopen the part and accept the auto-save recovery.
